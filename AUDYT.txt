================================================================================
                     OPIS PROJEKTU
================================================================================

Drive App to aplikacja do wspolnej jazdy samochodem — polaczenie Waze
z aplikacja spolecznosciowa dla kierowcow.

Stack technologiczny:
  - Next.js 16.2.2 (App Router) + React 19
  - TypeScript 5.x
  - Prisma 7.6.0 + @prisma/adapter-pg (driver adapter)
  - PostgreSQL
  - Socket.IO 4.8.3 (real-time)
  - Mapbox GL JS / react-map-gl
  - Zustand 5 (state management)
  - NextAuth v5 beta (autentykacja)
  - Tailwind CSS v4
  - Vitest (testy jednostkowe)
  - server.js (custom Node.js server — wymagany przez Socket.IO)

Glowne funkcje:
  - Mapa z markerami w czasie rzeczywistym
  - Raporty drogowe (policja, wypadki, fotoradary)
  - Konwoje (jazda grupowa z czatem, wspolnym celem)
  - Stacje paliw z cenami w czasie rzeczywistym
  - Nawigacja turn-by-turn (Mapbox Directions API)
  - Rejestrowanie i historia podrozy
  - System znajomych z lokalizacja na mapie
  - Kanał społecznościowy (posty, komentarze, polubienia)
  - Spoty (punkty spotkan)
  - Spotify integracja
  - Mystery Drive (losowa trasa)
  - Udostepnianie lokalizacji znajomym w czasie rzeczywistym

------------------------------------------------------------
POLACZENIA SOCKET.IO W APLIKACJI
------------------------------------------------------------

Aplikacja utrzymuje DWIE niezalezne instancje Socket.IO:

1. useNotifications (zawsze aktywny dla zalogowanego uzytkownika)
   - Dolacza do pokoju: user:${userId}
   - Dolacza do pokoju: convoy:${convoyId} (jesli w konwoju)
   - Odbiera: friend-request, friend-accepted, convoy-invite,
              convoy-update, convoy-destination-set, new-report,
              friend-location-update

2. useSocket (aktywny TYLKO gdy uzytkownik jest w konwoju)
   - Dolacza do pokoju: convoy:${convoyId}
   - Wysyla: location-update, join-convoy, leave-convoy
   - Odbiera: location-update, new-report, remove-report, report-vote,
              convoy-update, fuel-price-update, spot-created,
              spot-updated, spot-closed, convoy-destination-set

------------------------------------------------------------
EVENTY SOCKET.IO - PELNA LISTA
------------------------------------------------------------

KLIENT -> SERWER:
  user-connect          { userId }                      Dolacza do pokoju user:${userId}
  join-convoy           { convoyId, userId, name, ... } Dolacza do konwoju (emit member-joined)
  leave-convoy          { convoyId, userId, name }      Opuszcza konwoj (emit member-left)
  location-update       { convoyId, memberId, lat, ... } Aktualizacja pozycji
  join-convoy-notify    { convoyId }                    Dolacza do pokoju do powiadomien
  convoy-chat           { convoyId, userId, name, text } Wiadomosc tekstowa

SERWER -> KLIENT (broadcast do pokoju convoy:${convoyId}):
  location-update       { memberId, latitude, longitude, heading, speed, name, avatarUrl }
  convoy-update         { type, member?, memberId?, memberName? }
                          type: 'member-joined' | 'member-left' | 'member-online' | 'member-offline'
  convoy-destination-set { convoyId, destLat, destLng, destName }
  convoy-chat           { userId, name, text, timestamp }

SERWER -> KLIENT (broadcast do wszyskich / do pokoju):
  new-report            Report (obiekt)
  remove-report         { reportId }
  report-vote           { reportId, upvotes, downvotes }
  fuel-price-update     FuelStation (obiekt)
  spot-created          Spot (obiekt)
  spot-updated          Spot (obiekt)
  spot-closed           { spotId }

SERWER -> KLIENT (do pokoju user:${userId}):
  friend-request        { fromName, fromId }
  friend-accepted       { fromName, fromId }
  convoy-invite         { convoyId, convoyName, invitedByName }
  friend-location-update { userId, name, image, latitude, longitude, speed, heading }

------------------------------------------------------------
PRZEPLYWY DANYCH
------------------------------------------------------------

A) LOKALIZACJA ZNAJOMEGO:
  useLocationPing (co 5s) -> POST /api/users/me/location { lat, lng, speed, share: true }
  -> API route pobiera listę znajomych
  -> io.to(`user:${friendId}`).emit('friend-location-update', payload)
  -> useNotifications socket odbiera event
  -> useMapStore.setFriendLocation()
  -> FriendMarker renderuje sie na mapie

B) RAPORT DROGOWY:
  MapView -> POST /api/reports
  -> server.js io.emit('new-report', report)
  -> useSocket.on('new-report') -> useMapStore.addReport()
  -> ReportMarker pojawia sie na mapie

C) AKTUALIZACJA LOKALIZACJI W KONWOJU:
  useRealTimeLocation -> useSocket.emit('location-update', data)
  -> server.js io.to(convoyRoom).emit('location-update', data)
  -> useSocket.on('location-update') -> useMapStore.updateConvoyMember()
  -> ConvoyMarker aktualizuje pozycje

------------------------------------------------------------
ZNANE PROBLEMY W SCHEMACIE
------------------------------------------------------------

PROBLEM 1: FuelStation przechowuje ceny jako JSON pole prices
  Zamiast oddzielnej tabeli FuelPrice z historia
  -> Nie mozna pokazac historii cen (brak rekordow historycznych)
  -> Nie mozna porownac cen w czasie

PROBLEM 2: Brak modelu Notification (push/in-app)
  Powiadomienia sa tylko in-memory przez Socket.IO
  -> Po odswiezeniu strony trafia w proznię
  -> Brak historii powiadomien

PROBLEM 3: waypoints w Route to JSON (brak typowania Prisma)
  Musimy castowac recznie z Prisma.JsonValue
  -> Potencjalne bledy runtime jesli format sie zmieni

PROBLEM 4: ConvoyMember nie ma pola leftAt
  Mozna sprawdzic tylko czy jest aktywnym czlonkiem
  -> Brak historii dolaczania/odchodzenia

PROBLEM 5: Brak modelu dla geofencing / alertow
  Uzytkownik nie moze zapisac "alerty dla raportu w strefie XY"

SEC1. Sanityzacja contentu postow [WAZNE]
    Plik: src/app/api/posts/route.ts
    Problem:
      content: z.string().max(5000) - brak sanityzacji HTML
      Jesli content jest renderowany z dangerouslySetInnerHTML -> XSS
    Jak naprawic:
      npm install dompurify @types/dompurify
      const sanitized = DOMPurify.sanitize(content, { ALLOWED_TAGS: [] });
      lub po prostu nie renderuj jako HTML - uzyj {content} w JSX (bezpieczne)

SEC2. Weryfikacja ze raport nalezy do uzytkownika przed DELETE [WAZNE]
    Plik: src/app/api/reports/[id]/route.ts
    Sprawdz: czy WHERE zawiera userId: session.user.id
    Jesli nie, kazdy moze usunac dowolny raport.

SEC3. Limity rozmiaru uploadow [WAZNE]
    Problem:
      Brak limitu na rozmiar body requestow.
      Atakujacy moze wyslac 100MB JSON powodujac OOM.
    Jak naprawic:
      W server.js:
        app.use(express.json({ limit: '1mb' }));
      lub w Next.js next.config.ts:
        experimental: { serverActions: { bodySizeLimit: '1mb' } }

SEC4. Weryfikacja wlasciciela przy usuwaniu komentarzy [WAZNE]
    Plik: src/app/api/posts/[id]/comments/[cid]/route.ts
    Sprawdz: czy DELETE weryfikuje ze komentarz nalezy do session.user.id

SEC5. Logowanie probow blednego logowania [SREDNIE]
    Problem: Brak logowania nieudanych prob logowania.
    Po 5 nieudanych probach -> blokada konta na 15 min (ochrona bruteforce).

------------------------------------------------------------
ZNANE WASKIGARDLA
------------------------------------------------------------

PERF1. Brak Redis cache dla czesto odpytywanych endpointow
    Kandydaci do cache (TTL 60s):
      GET /api/fuel (stacje paliw nie zmieniaja sie czesto)
      GET /api/routes/public (publiczne trasy)
      GET /api/dashboard/stats
    Implementacja:
      npm install ioredis
      W API routes:
        const cached = await redis.get(cacheKey);
        if (cached) return NextResponse.json(JSON.parse(cached));
        const data = await prisma...;
        await redis.setex(cacheKey, 60, JSON.stringify(data));
        return NextResponse.json(data);

PERF2. N+1 problem w FriendsList
    Plik: src/app/api/friends/route.ts
    Problem:
      Prawdopodobnie dla kazdego znajomego jest osobne zapytanie o status online.
    Jak naprawic:
      Include: { user: { select: { id, name, image, lastLocationAt } } }
      w jednym zapytaniu zamiast N+1

PERF3. Brak lazy loading obrazow
    Problem: Wszystkie obrazy avatarów sa ladowane eagerly.
    Jak naprawic:
      Uzyj next/image z loading="lazy"
      lub <img loading="lazy" />

PERF4. Brak debounce w wyszukiwarce [LATWY]
    Plik: src/components/friends/AddFriendModal.tsx
    Problem:
      Prawdopodobnie GET /api/users?search= jest wywolywany przy kazdym keystroke.
    Jak naprawic:
      import { useDebounce } from 'use-debounce';
      const [debouncedSearch] = useDebounce(search, 300);
      useEffect(() => { fetchUsers(debouncedSearch); }, [debouncedSearch]);

PERF5. Mapbox tiles - brak optymalizacji
    Problem:
      Przy slabym polaczeniu internetowym tiles laduja sie wolno.
    Jak naprawic:
      Konfiguracja Mapbox: fadeDuration: 0 (przyspiesza rendering)
      Prefetch tiles dla aktualnej lokalizacji

PERF6. Socket.IO - brak namespace oddzielenia
    Problem:
      Wszystkie eventy sa w domyslnym namespace '/'.
      Przy wielu uzytkownikach wszystkie eventy przechodzą przez jeden namespace.
    Jak naprawic:
      const convoy = io.of('/convoy');
      const notifications = io.of('/notifications');
